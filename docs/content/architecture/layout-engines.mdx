# Pluggable Layout Engines

Layout in `native-view-engine` is decoupled from rendering through two narrow traits in `packages/core/layout` (`nve-layout`): **`StoreLayoutEngine`** and **`TextMeasurer`**. Backends like `HeadlessBackend<L>` and `SkiaBackend<L>` are generic over `L: StoreLayoutEngine` — giving zero-vtable monomorphization by default while allowing live mid-session engine switching through `DynLayoutEngine` (`Box<dyn StoreLayoutEngine>`). Core crates and backends never depend on an optional engine: hosts inject one through `with_layout(...)`.

## Core Traits

```rust title="packages/core/layout/src/{measure,engine}.rs (excerpt)"
pub trait TextMeasurer: Send + Sync {
    /// Returns (width, height) in logical points under an optional max_width wrap constraint.
    fn measure(&self, text: &str, font_size: f32, max_width: Option<f32>) -> (f32, f32);
}

pub trait StoreLayoutEngine: Send {
    fn name(&self) -> &'static str;
    /// Invalidates cached entries for every layout/measure/structural change in `changes`.
    fn sync_changes(&mut self, store: &NodeStore, changes: &ChangeSet);
    /// Self-gated: returns `false` without a pass when nothing that affects layout changed.
    fn compute_layout(&mut self, store: &NodeStore, root: NodeId, viewport: Viewport) -> bool;
    fn layout_of(&self, id: NodeId) -> Option<LayoutRect>;
    fn set_text_measurer(&mut self, measurer: Arc<dyn TextMeasurer>);
    fn reset(&mut self);
}
```

All coordinates returned by `layout_of(id)` are normalized to **surface-space (root-relative) logical points**, eliminating coordinate-system divergence between backends.

## Built-In Layout Engines

| Engine | Crate | Implementation | 100 Rows | 1,000 Rows | Best For |
| :--- | :--- | :--- | ---: | ---: | :--- |
| **Taffy** (`TaffyStoreLayout`, default) | `nve-layout` | Pure Rust (`taffy 0.16.0`) | **168.5 µs** | **1.77 ms** | Default Skia, WASM, headless CI, zero-C++ builds |
| **React Native Yoga** (`YogaLayoutEngine`, opt-in module) | `nve-layout-yoga` | Real C++20 `yogacore` via FFI | **76.2 µs** (custom measurer) | **801.6 µs** (custom measurer) | Bit-exact React Native Fabric parity |
| **C++ Standalone Flexbox** | `cxx/nve-fabric-bridge` | Zero-dep C++20 Flexbox solver | **44.7 µs** | **450.7 µs** | Native C++ hosts built without `RN_REACT_COMMON_DIR` |

### Dynamic Dispatch Overhead: Effectively Zero

Measured in `benchmarks/baseline.json` comparing statically monomorphized `TaffyLayoutEngine` against `DynLayoutEngine` (`Box<dyn LayoutEngine>`):

- **100 rows:** `170.1 µs` static vs. `175.5 µs` `dyn Box` (+3.1%)
- **1,000 rows:** `1.773 ms` static vs. `1.783 ms` `dyn Box` (+0.56%)

Because layout traversal dominates execution time, boxing the engine for runtime hot-switching adds less than 1% overhead at 1,000 nodes.

## Real React Native Yoga (`nve-layout-yoga`)

`packages/modules/layout-yoga` compiles React Native's actual `yogacore` C++20 sources when `RN_REACT_COMMON_DIR` is set at build time, bridging `YGNodeSetMeasureFunc` directly back into any Rust `TextMeasurer` (such as `CosmicTextEngine` or `HeuristicTextMeasurer`):

- **Heap-stable measure contexts** — Each node's `BoxedMeasureState` (`NveYogaMeasureHook` + `MeasurePayload`) lives behind a `Box`, so rehashing the internal `HashMap<NodeId, YogaNodeEntry>` never invalidates pointers stored in `YGNodeSetContext`.
- **Panic-safe measure callbacks** — `rust_measure_callback` wraps `TextMeasurer::measure` in `catch_unwind` so a panicking measurer never unwinds into C++ Yoga.
- **Graceful fallback without RN checkout** — When `RN_REACT_COMMON_DIR` is omitted, `nve-layout-yoga` still compiles cleanly on every machine; `YogaLayoutEngine::is_available()` returns `false` and `YogaLayoutEngine::new()` returns `Err(YogaUnavailableError)`.

```bash title="Enable real React Native Yoga in Rust and C++ builds"
export RN_REACT_COMMON_DIR=/path/to/react-native/packages/react-native/ReactCommon
cargo test -p nve-layout-yoga
```

## Text Measurement Parity

Every host registers its native shaping engine as a `TextMeasurer` so multi-line wrapping and intrinsic sizing match platform typography pixel-for-pixel:

- **Skia Desktop (`nve-backend-skia`)** — `CosmicTextEngine` (`cosmic-text 0.19.0`)
- **macOS / iOS (`hosts/apple-common`)** — CoreText / `NSAttributedString`
- **Windows (`hosts/windows-shell`)** — DirectWrite `IDWriteTextLayout::GetMetrics` (`DirectWriteTextMeasurer`)
- **Linux GTK4 (`hosts/gtk-shell`)** — Pango `PangoLayout` with `PANGO_WRAP_WORD_CHAR`
- **Qt 6 (`hosts/qt-shell`)** — `QFontMetricsF` / `QTextLayout`
- **Headless & Fallback** — `HeuristicTextMeasurer` (`font_size * 0.58` char advance, `font_size * 1.35` line height, explicit `\n` and `max_width` wrap support)

## Live Mid-Session Switching

Applications and tools like **NVE Studio** can swap between Taffy and Yoga on a live surface without losing UI state:

1. Construct the backend with `DynLayoutEngine` (`Box::new(TaffyLayoutEngine::new())`).
2. When the user toggles the layout engine, replace the boxed engine, install the active `Arc<dyn TextMeasurer>`, replay the retained node tree's layout/style/text/children props into the new engine, and run `compute_layout(root, viewport)`.
3. Emit a fresh `NveSceneView` or display list — the diffing pipeline updates only nodes whose computed rectangles actually shifted.

<Callout kind="tip" title="Debugging layout divergence">
Because `HeadlessBackend<TaffyLayoutEngine>` and `HeadlessBackend<YogaLayoutEngine>` consume the exact same `CommandBuffer` bytes and `HeuristicTextMeasurer`, you can assert sub-pixel parity between Taffy and Yoga in `< 5 ms` unit tests without booting any GUI.
</Callout>

# 2-Tier Hot Reload

Iteration speed is an architectural invariant in `native-view-engine`. Native host shells (macOS AppKit, iOS Simulator, Android Emulator, Windows Direct2D, Qt 6, GTK4, Skia) are compiled **once**, while `cargo nve dev` streams live updates to every connected client over a unified 2-tier WebSocket protocol (`HotPatchMsg`).

## The 4-Tier Iteration Budget

| Tier | Trigger | Budget | Mechanism |
| :--- | :--- | :--- | :--- |
| **Tier 0: Headless** | `cargo test` / `cargo nve inspect` | **< 300 ms** | Pure-Rust `nve-backend-headless` (`taffy`) + the C++20 `host-cxx` suites via Ninja + `kache`/`ccache`. |
| **Tier 1: RSX / Style Patch** | Edit static text, `nve_style: TypedStyle::...` literal chains, or standalone numeric layout props | **< 50 ms** | `nve-cli` computes an AST diff of the edited `.rs` file and broadcasts a binary `NVP1` v2 `HotPatchMsg::TemplatePatch` carrying flat `RowPatch` words over WebSocket. Zero recompile and zero runtime CSS parser; works on **physical iOS/Android devices and browsers**. |
| **Tier 2: Rust Logic Swap** | Edit Rust logic, signals, event handlers, or types | **150–400 ms** | `nve dev` rebuilds only the app `cdylib` (`kache` + `-C split-debuginfo=unpacked`), stamps a versioned library filename, and broadcasts `HotPatchMsg::DylibReload`. Hosts snapshot state, `dlopen` the new generation, and restore state atomically. |
| **Tier 3: C++ Hosts** | Edit `packages/core/host-cxx` or `hosts/*` | **1–3 s** | `libnve_runtime` is built once; `host-cxx` is header-only, so Ninja + `ccache` recompiles only the touched host sources. |

## Binary Wire Protocol (`NVP1`)

`packages/core/engine/src/hotreload.rs` encodes `HotPatchMsg` using the compact **`NVP1`** binary framing (`HOT_PATCH_WIRE_MAGIC = *b"NVP1"`, capped at `MAX_WIRE_ITEMS = 65_536` per collection to guard against corrupt packets):

```rust title="packages/core/engine/src/hotreload.rs" highlight="2-15,17-22"
pub enum HotPatchMsg {
    /// Tier 1 (< 50 ms): Surgical text & binary `RowPatch` word updates with zero Rust recompile.
    TemplatePatch {
        generation: u64,
        template_key: u64,
        node_path: Vec<u16>,
        target_test_id: Option<String>,
        row_patch_words: Vec<u32>,
        text_updates: Vec<(usize, String)>,
        text_replacements: Vec<(String, String)>,
    },
    /// Tier 2 (150–400 ms): Atomic state-preserving cdylib hot-swap.
    DylibReload {
        generation: u64,
        dylib_path: String,
        build_ms: u64,
    },
    /// Live latency HUD banner update.
    DevStatus {
        message: String,
        latency_ms: u64,
    },
}
```

## How Tier-1 RSX Diffing Works

When you save a Rust file while `cargo nve dev` is running:

1. `packages/tools/cli/src/rsx_diff/` parses the previous and new `rsx! { ... }` blocks and classifies the edit.
2. If only static text literals, `nve_style: TypedStyle::...` literal builder arguments, or standalone numeric layout props changed (measured at `< 2.5 ms` for the AST diff), `nve dev` skips `cargo build` completely and broadcasts `HotPatchMsg::TemplatePatch` with exact `template_key`, structural `node_path`, optional `target_test_id`, binary `row_patch_words`, and `text_replacements`.
3. `DioxusSurface::apply_hot_patch` (via `NveDevApi::apply_hot_patch`) validates `RowPatchView::from_words` and applies packed word updates directly onto the live `NodeStore` in **< 2 µs** with **zero** steady-state heap allocations and emits a minimal incremental `NVE2` delta frame.
4. All Dioxus signals, scroll positions, focused `TextInput`s, and navigation stacks remain untouched.

## How Tier-2 `cdylib` Hot-Swap Preserves State

When Rust logic, signal types, or event handlers change, `nve dev` falls back to Tier 2:

:::steps
::step{title="Incremental cdylib rebuild"}
`cargo build -p <package>` runs with `[profile.dev.package."*"] opt-level = 2` (so dependencies are never rebuilt) and `-C split-debuginfo=unpacked` on macOS (skipping `dsymutil`). The resulting `.dylib`/`.so`/`.dll` is copied to a generation-stamped path so `dlopen` / `LoadLibrary` never returns a cached image handle.
::step{title="Snapshot live app state"}
On receiving `HotPatchMsg::DylibReload`, the host invokes `old_dev_api->snapshot_state(old_handle)` (typically backed by `SignalArchive` `NVE_SIG1` or app binary state).
::step{title="Load new generation via nve_get_interface"}
The host `dlopen`s the new library, resolves `nve_get_interface`, fetches `NVE_IFACE_SURFACE`, `NVE_IFACE_DEV`, and `NVE_IFACE_HOST`, creates `new_handle = new_surface_api->create(surface_id)`, and re-binds `NveHostCallbacks`.
::step{title="Restore state and render Frame 0"}
The host calls `new_dev_api->restore_state(new_handle, snapshot_slice)`, renders the first frame from the new generation, destroys the old handle, and unloads the previous library generation.
:::

## Running `nve dev`

```bash title="Watch studio-workspace with live Skia preview and optional Web rebuild"
# Native Skia desktop window connected to ws://127.0.0.1:8089
cargo nve dev --package nve-studio-workspace --skia

# Also rebuild hosts/web-shell WASM on save and serve live NveWireFrame pairing on LAN
cargo nve dev --package nve-studio-workspace --host 0.0.0.0 --port 8089 --web --pair
```

With the web rebuild on, `nve dev` also serves `hosts/web-shell` on `--web-port` (default
`8088`). Opening `http://<host>:8088/` redirects to the `dev` bundle wired to the daemon's
hot-reload socket (`?ws=ws://<host>:8089`). Production bundles (`pkg/studio`, `pkg/kitchen-sink`) contain
no hot-reload code.

<Callout kind="info" title="Physical iOS and Android devices">
On physical iOS devices (where dynamic `dlopen` of unsigned libraries is restricted by the OS), Tier-1 `NVP1` patches still deliver `< 50 ms` style and copy iteration over Wi-Fi, while **live `NveWireFrame` pairing** (`--pair`) streams full logic updates from your workstation to the device thin client at 60fps without rebuilding or re-signing the app.
</Callout>

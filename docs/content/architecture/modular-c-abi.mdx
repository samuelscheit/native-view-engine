# Modular C ABI (`nve_get_interface`)

Instead of exporting a monolithic vtable that grows with every new engine capability and breaks binary compatibility, every NVE Rust module exports **one** C symbol:

```c title="nve_abi.generated.h"
const void* nve_get_interface(uint32_t interface_id);
```

Hosts resolve `nve_get_interface` once via `dlsym` / `GetProcAddress` (or direct static linking), query the small 2-to-5 function `const` interface tables they need, and invoke them directly in CPU registers (**0.98 ns** lookup, **1.33 ns** render-slice call).

## The 5 Standard Interfaces

Defined in `packages/core/abi/src/ffi.rs` and `packages/core/abi/src/host.rs`, locked at compile time by the 64-bit XXH64 `NVE_CORE_ABI_SCHEMA_HASH`:

| ID | Constant | C Struct | Required? | Functions |
| :--- | :--- | :--- | :--- | :--- |
| `1` | `NVE_IFACE_SURFACE` | `NveSurfaceApi` | **Required** | `create`, `destroy`, `render`, `dispatch_events(handle, NveEventBatch)` |
| `2` | `NVE_IFACE_LAYOUT` | `NveLayoutApi` | Optional | `measure(handle, NveSizeConstraints) -> NveIntrinsicSize`, `hit_test(handle, x, y, pointer_phase) -> u8` |
| `3` | `NVE_IFACE_COMPONENT` | `NveComponentApi` | Optional | `set_props(handle, const NveMapEntry*, uint32_t)`, `drain_emitted_events(handle) -> NveEventBatch` |
| `4` | `NVE_IFACE_DEV` | `NveDevApi` | Optional (dev) | `apply_hot_patch`, `snapshot_state`, `restore_state` |
| `5` | `NVE_IFACE_HOST` | `NveHostApi` | Optional | `bind_host(handle, const NveHostCallbacks*)`, `dispatch_host_events(handle, NveBufferSlice)` |

Custom hybrid modules generated by `cargo nve codegen hybrid` allocate deterministic interface IDs starting at `NVE_HYBRID_INTERFACE_ID_BASE` (`compute_hybrid_interface_id`) without colliding with `1..=5`.

### Register-Only Scalar Layout & Gesture Calls

`NveLayoutApi` passes `NveSizeConstraints { min_w, min_h, max_w, max_h }` and returns `NveIntrinsicSize { width, height }` purely in floating-point registers — **3.55 ns** for `measure` and **8.72 ns** for `hit_test` (`NveGestureDisposition`: `1 = Claim`, `2 = PassThrough`, `3 = DeferToParent`).

### Zero-Copy Direct Props & Events

`NveComponentApi::set_props` and `NveSurfaceApi::dispatch_events` pass `#[repr(C)]` tagged `NveValue` trees (`NveMapEntry`, `NveEventBatch`) borrowed directly from a caller-owned bump arena (such as Swift's `NveDirectArena` or C++'s stack arena). Reading a nested field through Rust's `NveValueRef` takes **17.09 ns** with zero deserialization and zero heap allocations.

## Host-Capability Interface (`NVE_IFACE_HOST = 5` & `NVH1`)

`NVE_IFACE_HOST = 5` gives Rust apps binary access to modular native OS capabilities (`packages/core/host-services` + `packages/modules/*`) and `WindowManager` (`SERVICE_WINDOW = 0x0002`) without adding platform-specific FFI symbols. In-process Rust hosts dispatch directly to typed `*Backend` traits with zero wire serialization, while cross-language hosts cross `NVE_IFACE_HOST = 5`:

1. Immediately after `create(surface_id)`, the host calls `NveHostApi::bind_host(handle, &NveHostCallbacks { host_ctx, invoke, channel_publish })`.
2. Sync capabilities write directly into a stack-allocated caller buffer (`FFI_STACK_BUF_SIZE`) via `invoke(...)`. If the buffer is too small, the host returns `NveHostStatus::BufferTooSmall (-1)` and sets `*out_len = required_bytes` so the caller retries once with an exact allocation.
3. Async capabilities (such as native file pickers or notification permission dialogs) return `NveHostStatus::Pending (1)` and later deliver their result in an **`NVH1`** binary host-event batch via `NveHostApi::dispatch_host_events`.

### Reserved Built-In Service IDs (`0x0001..0x00FF`)

| Service ID | Constant | Subsystem |
| :--- | :--- | :--- |
| `0x0001` | `SERVICE_CHANNEL` | `NveChannelBus` cross-surface pub/sub |
| `0x0002` | `SERVICE_WINDOW` | Multi-window lifecycle (`NVW1`) |
| `0x0010` | `SERVICE_CLIPBOARD` | Native OS clipboard text read/write |
| `0x0011` | `SERVICE_FILESYSTEM` | Open/save file pickers & standard OS paths |
| `0x0012` | `SERVICE_SECURE_STORE` | Keychain / Credential Manager / Keystore |
| `0x0013` | `SERVICE_LINKING` | External URL open & inbound deep links |
| `0x0014` | `SERVICE_SYSTEM_ENV` | Live Theme (`NVT2`) & Locale (`NVL1`) snapshots |
| `0x0015` | `SERVICE_NOTIFICATIONS` | Local user notifications & tap events |
| `0x0016` | `SERVICE_HAPTICS` | Impact, selection, and notification haptics |

### `NVH1` Host-Event Batch Format

Every `NVH1` batch starts with a 12-byte header (`magic = "NVH1"`, `version = u16(1)`, `flags = u16(0)`, `record_count = u32`) followed by tagged records (`1 = AsyncResponse`, `2 = HostPushEvent`, `3 = ChannelMessage`).

## Safe Rust Authoring: `NveApp` & `export_nve_app!`

Application authors never write `extern "C"` or `unsafe` pointers. Implement `nve_engine::NveApp` and invoke `export_nve_app!`:

```rust title="Safe NveApp trait implementation with panic-safe C ABI export" highlight="1-2,17-22"
use nve_abi::{FrameId, NveHostCallbacks, SurfaceId};
use nve_engine::NveApp;

pub struct MyApp { /* ... */ }

impl NveApp for MyApp {
    fn create(surface_id: SurfaceId) -> Self { todo!() }
    fn render(&mut self, frame_id: FrameId) -> &[u8] { &[] }
    fn dispatch_events(&mut self, encoded_events: &[u8]) -> bool { false }

    // Optional overrides:
    fn bind_host(&mut self, callbacks: NveHostCallbacks) { let _ = callbacks; }
    fn dispatch_host_events(&mut self, nvh1_batch: &[u8]) -> bool { false }
    fn snapshot_state(&mut self) -> &[u8] { &[] }
    fn restore_state(&mut self, state: &[u8]) { let _ = state; }
}

#[cfg(feature = "cdylib-export")]
mod cdylib_export {
    nve_engine::export_nve_app!(super::MyApp);
}
```

## FFI Panic Isolation

Unwinding a Rust panic across an `extern "C"` boundary is Undefined Behavior. Every trampoline generated by `export_nve_app!` wraps user code inside `nve_engine::app::ffi_catch_unwind`:

- **Zero hot-path cost** — Normal non-panicking calls never touch thread-local storage.
- **Safe fallback values** — On panic, `ffi_catch_unwind` catches the payload, stores a formatted message in `LAST_FFI_PANIC` (readable via `last_ffi_panic()` / `take_last_ffi_panic()`), and returns safe defaults (`NULL` handle, `NveBufferSlice::EMPTY`, `0` redraw flag, `NveGestureDisposition::PassThrough`).
- **Release profile guarantee** — `[profile.release]` in root `Cargo.toml` explicitly keeps `panic = "unwind"` so native `cdylib` plugins and embedded surfaces retain panic isolation even in optimized builds.

<Callout kind="danger" title="Always gate export_nve_app! in a private submodule">
When a crate is compiled both as an `rlib` (for workspace tests or WASM shells) and as a `cdylib`, put `export_nve_app!` inside `#[cfg(feature = "cdylib-export")] mod cdylib_export { ... }`. This isolates the `nve_get_interface` symbol into its own codegen unit and prevents MSVC `LNK2005` duplicate-symbol link errors.
</Callout>

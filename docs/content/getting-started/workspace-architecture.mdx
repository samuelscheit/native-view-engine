# Workspace Architecture

The `native-view-engine` monorepo enforces a strict, layered dependency DAG. Low-level ABI and engine crates compile in hundreds of milliseconds and have zero dependency on Dioxus, Skia, or browser bindings.

## Dependency DAG

```text
                       ┌──────────────────────┐
                       │       nve-abi        │  Uniform 64B NveEvent + NVEV v2 EventRing,
                       │   (no heavy deps)    │  NveSceneView (32B NodeRow), NveValue, C ABI
                       └──────────┬───────────┘
           ┌──────────────────────┼──────────────────────┐
           ▼                      ▼                      ▼
   ┌───────────────┐      ┌───────────────┐      ┌───────────────┐
   │  nve-tables   │      │  nve-engine   │      │  nve-interop  │
   │Core NveTables │      │NveApp, Layout │      │Surfaces, CRDT │
   │FlatResources  │      │Frame0 + State │      │NveCrdtDelta   │
   └───────┬───────┘      └───────┬───────┘      └───────┬───────┘
           │                      │                      │
     ┌─────┴──────────┬───────────┼───────────┬──────────┴─────┐
     ▼                ▼           ▼           ▼                ▼
┌──────────┐  ┌────────────┐ ┌───────────┐ ┌─────────┐ ┌──────────────┐
│nve-dioxus│  │nve-layout- │ │nve-host-  │ │nve-back-│ │nve-codegen   │
│rsx!+sig  │  │yoga (C++20)│ │services + │ │ends     │ │5-target + ABI│
└────┬─────┘  └────────────┘ │modules/*  │ └────┬────┘ └──────────────┘
     ├──────────────┬────────┴─────┬─────┘      │
     ▼              ▼             ▼           ▼
┌──────────┐  ┌──────────┐  ┌──────────┐ ┌────────────────────────────┐
│  nve-ui  │  │nve-router│  │ nve-mdx  │ │ Hosts & Shells             │
│15 comps  │  │NVN1 + web│  │NVS2 index│ │ libnve_runtime + host-*    │
└────┬─────┘  └────┬─────┘  └────┬─────┘ │ hosts/{apple,win,qt,gtk,   │
     └─────────────┴─────────────┘       │ android,compose,swiftui,   │
                   ▼                     │ flutter,skia,web}          │
             ┌──────────┐                └────────────────────────────┘
             │ nve-docs │
             └──────────┘
```

<Callout kind="warning" title="Strict framework-agnostic boundary">
`packages/core/engine` MUST maintain zero dependency on `dioxus-core` or `dioxus-signals`. All Dioxus `WriteMutations` bridging, RSX attributes, and `SignalArchive` hydration live exclusively inside `packages/core/dioxus`.
</Callout>

## Rust Workspace Packages (`packages/`)

The root `Cargo.toml` defines 33 workspace members split into core runtime (`packages/core/`), backends (`packages/backends/`), application frameworks (`packages/framework/`), tooling (`packages/tools/`), opt-in capability modules (`packages/modules/`), host shells (`hosts/`), and runnable examples (`examples/`):

| Crate | Path | Responsibility |
| :--- | :--- | :--- |
| `nve-abi` | `packages/core/abi` | Uniform pointer-free 64-byte `NveEvent` + `NVEV` v2 `EventRing` / `NveEventBatch`, `TableDesc`, the single `NveSceneView` (32-byte `NveNodeRow` + 16-byte `NveLayoutRect` slabs), `#[repr(transparent)]` domain handles, `NveValue` bump-arena types, and `nve_get_interface(1..=5)`. |
| `nve-tables` | `packages/core/tables` | Pure, platform-agnostic `#[derive(NveTable)]` core tables (`Layout`, `Visual`, `Typography`, `Text`, `Interaction`, `Scroll`, `TextInput`, `Image`, `Accessibility`, `Transform2D`) and core `FlatResource` specs (`ImageSrc`, `BoxShadows`, `BackgroundFill`, `GridTracks`, `StateRules`). |
| `nve-canvas` | `packages/modules/canvas` | Standalone `nve.canvas` table and canonical 4-byte-aligned `FlatResource` `nve.res.draw_list` vector draw-list IR (`DrawList`, `DrawListRecorder`, `DrawListView`) with leaf `web/`, `skia/`, and C++20 `cxx/` renderers. |
| `nve-engine` | `packages/core/engine` | `NveApp` trait + `export_nve_app!` panic-safe C ABI macro, `StoreBackend`, `StoreWireReplica`, `SurfaceRunner`, 6-stage `FrameProfiler`, zero-`unsafe` `Frame0File` (`frame0.nve2`) + atomic `StateFile` (`state.nve`), `HotPatchMsg` (`NVP1`), and `cdylib` loader. |
| `nve-layout` | `packages/core/layout` | Shared `StoreLayoutEngine` + `TextMeasurer` traits and the default direct `TaffyStoreLayout` engine used by headless, Skia, and the host runtime. |
| `nve-layout-yoga` | `packages/modules/layout-yoga` | Opt-in real C++20 React Native Yoga (`yogacore`) `StoreLayoutEngine` module with `YGNodeSetMeasureFunc` callbacks to Rust `TextMeasurer` (gracefully degrades when `RN_REACT_COMMON_DIR` is unset). |
| `nve-dioxus` | `packages/core/dioxus` | Dioxus `0.7.10` `WriteMutations` adapter emitting `CommandBuffer`s, native-first `dioxus_elements` (`view`, `text`, `pressable`, `scrollview`, `image`, `textinput`, `skia_canvas`), 12 ARIA/`tabIndex` attributes, Tier-1 RSX hot-patcher, and `SignalArchive` (`NVE_SIG1`/`NVE_SGD1`). |

| `nve-interop` | `packages/core/interop` | `SurfaceOrchestrator`, `LayoutNegotiator`, `GestureArbitrator`, `NveChannelBus`, `<Island>` `RenderHandoff`, `WindowManager` (`NVW1`), panic-isolated `NvePluginHost`, `NVC1` binary CRDT engine, and `NVT1`/`NVD1` live delta transport. |

| `nve-mdx` | `packages/framework/mdx` | Zero-dependency pure-Rust `.md`/`.mdx` parser, Nextra-style `_meta.toml` nav builder, compile-time schema/link/anchor validator, multi-language syntax highlighter, and binary `NVS2` full-text search index. |

## Runtime & Platform Host Shells (`packages/core/host-*`, `hosts/`)

Every native shell runs on one engine, `libnve_runtime` (`packages/core/runtime`), which decodes `NVE1` `CommandBuffer`s, runs layout, owns app loading / hot reload / live pairing, and publishes a single `NveSceneView` straight from its `NodeStore` slabs. Hosts read it through the static per-language packages `packages/core/host-{cxx,swift,java,dart,ts}` (each with one `SceneReader`) and only mount native views:

- **`packages/core/host-cxx`** — Header-only C++20 host library: `SceneReader`, `TableReader`, `RuntimeSession`, `HostSession`, `RetainedTree<Adapter>` (O(changed) native-view reconciler), and shared launch / URL / controlled-text policy.
- **`hosts/apple-common/`** — Shared UIKit/AppKit ABI loader, hot-swap controller, `NveAppleSceneReconciler`, CoreGraphics `NveAppleCanvasView`, and `NveAppleImageCache` reused by `hosts/macos-shell` and `hosts/ios-shell`.
- **Desktop shells** — `hosts/skia-shell` (`winit` + GPU/`softbuffer`), `hosts/macos-shell` (AppKit + RN-macOS), `hosts/windows-shell` (Win32/Direct2D/DirectWrite + RNW 0.88 components), `hosts/qt-shell` (Qt 6 Widgets + Quick `QSGNode`), `hosts/gtk-shell` (GTK4/Pango/Cairo).
- **Mobile & embedder kits** — `hosts/ios-shell` (UIKit/iPadOS `UIScene`), `hosts/android-shell` (JNI DirectByteBuffers + zero-Gradle APK launcher), `hosts/compose-kit` (`dev.nve.compose`), `hosts/swiftui-kit` (`NveSwiftUI`), `hosts/flutter-plugin` (`nve_flutter`).
- **Web shell** — `hosts/web-shell` (`wasm-bindgen`, one production bundle per app plus a `dev` bundle, `ACTIVE_SHELLS` multi-window, `?pair=ws://` live pairing).

## Workspace Build Profiles

The root `Cargo.toml` tunes three Cargo profiles for fast iteration without sacrificing release or WASM size:

```toml title="Cargo.toml" highlight="2-6,10-13,17-22"
# Keep workspace crates fast to recompile while optimizing heavy deps once
[profile.dev]
opt-level = 0
debug = 1
[profile.dev.package."*"]
opt-level = 2
debug = 0

# Native release preserves panic = "unwind" for catch_unwind FFI isolation
[profile.release]
lto = "thin"
codegen-units = 1
panic = "unwind"

# Size-optimized browser WASM profile (285.8 KiB gzipped Studio bundle)
[profile.wasm-release]
inherits = "release"
opt-level = "z"
lto = true
codegen-units = 1
panic = "abort"
strip = "symbols"
```

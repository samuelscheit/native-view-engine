# Android & Jetpack Compose (`hosts/android-shell` + `hosts/compose-kit`)

Android hosts read the `NveSceneView` that `libnve_runtime` publishes (32-byte `NveNodeRow` rows, 16-byte `NveLayoutRect` rects, text/children slabs, delta indices, tables) straight from native memory into Java/Kotlin via persistent **`DirectByteBuffer`** views — binary, zero per-frame JNI object allocations, and zero GC pressure at 120fps.

## Zero-GC JNI Slab Transport (`hosts/android-shell`)

`libnve_android_shell` (`hosts/android-shell`) is the JNI half of `dev.nve.host.NativeRuntime`: it binds Java/Kotlin hosts to `libnve_runtime` through `nve::host::RuntimeSession`.

- `NveAndroidSceneJni.cpp` packs each acquired frame in the generated `NveJniFrame` layout: a `long[]` header plus cached `DirectByteBuffer` slabs (rows, rects, `text_slab`, `children_slab`, `dirty_indices`, `moved_indices`, `removed_ids`, `dirty_resources`, `scroll_offsets`, tables), each wrapped in a `GlobalRef` `java.nio.ByteBuffer` via `NewDirectByteBuffer`.
- The cached buffer is re-created **only** when a native slab pointer or capacity grows; empty slabs bind to a non-null sentinel with capacity `0` to avoid ART null-address quirks.
- Generated bindings live in package **`dev.nve.host.generated`** (`packages/core/host-java`): `NveAbi` (constants, `NVE_RUNTIME_SCHEMA_HASH` / `NVE_CORE_ABI_SCHEMA_HASH` as `Key64`, record layouts) and `NveTables` (word-table keys and field specs), read through `dev.nve.host.SceneReader` and the static `dev.nve.host` runtime.
- `NveAndroidEventsJni.cpp` encodes `EventRing` events into `NveDirectEvent` batches and calls the host text measurer back into Java (`NveTextMeasurer`, `StaticLayout`).
- **`NveCanvasView.java`** paints `NVE_DRAW1` vector draw lists directly onto `android.graphics.Canvas`; **`NveSceneRenderer`** turns scene frames into native Android Views in O(changed).
- **TalkBack accessibility** — `NveViewStyle` maps the accessibility tables of each node (label, role, hint, states) onto View semantics for Android's `AccessibilityNodeProvider`; there is no separate metadata slab.
- **Live pairing** — `NveAndroidRuntimeJni.cpp` connects the runtime to `cargo nve pair` without re-pushing `.so` binaries.

### Standalone Zero-Gradle APK & Emulator Launcher

`hosts/android-shell/run-emulator.sh` builds a signed `arm64-v8a` APK (`dev.nve.android`) directly using `$ANDROID_HOME` (`javac`, `d8`, `aapt2`, `zipalign`, `apksigner` — zero Gradle downloads) and installs/launches it on an Android Emulator:

```bash title="Build APK, launch on emulator, and run host-side JNI CTest"
# Build + verify signed APK only
./hosts/android-shell/run-emulator.sh nve-example-kitchen-sink --build-only

# Build and launch NVE Studio on Pixel_10 (or first available AVD)
./hosts/android-shell/run-emulator.sh nve-studio-workspace --screenshot /tmp/nve-android.png

# Host-side JNI CTest (runs natively without an emulator)
cmake -S hosts/android-shell -B hosts/android-shell/build -G Ninja \
  && cmake --build hosts/android-shell/build \
  && ctest --test-dir hosts/android-shell/build --output-on-failure
```

<Callout kind="warning" title="Avoid Eclipse OpenJ9 with Android build-tools d8">
On macOS arm64, running Android `build-tools/36.0.0/d8` under Eclipse OpenJ9 triggers a Scavenger GC assertion crash. `run-emulator.sh` automatically detects OpenJ9 and switches `JAVA_HOME` to a HotSpot/JBR JDK (e.g., Android Studio JBR or Temurin 21).
</Callout>

## Jetpack Compose Kit (`hosts/compose-kit`)

`dev.nve.compose` is a drop-in Android Library Gradle module for embedding NVE Rust surfaces directly inside Jetpack Compose apps:

- **`NveSurfaceController.kt`** — `NveSurfaceController` over `NativeRuntimeHost` (JVM fakes in tests): app `.so` loading with hot reload, `nve pair` pairing, and input → `EventRing` events (press, text change, submit, focus / blur, scroll).
- **`NveScene.kt`** — `NveSceneCapture` turns each acquired frame (`dev.nve.host.SceneReader` over the generated `NveTables` specs) into an immutable snapshot in O(changed), driven by `dirty_indices`, `moved_indices`, `removed_ids`, and `dirty_resources`; a new `scene_epoch` rebuilds everything.
- **`NveSurface.kt` (`@Composable fun NveSurface`)** — Draws the snapshot (`BasicText`, `BasicTextField`, `Image`, `Canvas` + `NveDrawListRenderer` for `NVE_DRAW1`, scroll containers) with Compose semantics (roles, content descriptions) and `requestDisallowInterceptTouchEvent` gesture arbitration.
- **`NveHostActivity.kt`** — Reusable `ComponentActivity` preserving `surfaceId` across lifecycle transitions and supporting Tier-2 `.so` hot-reload.

```kotlin title="Embedding an NVE app in Jetpack Compose"
class MainActivity : ComponentActivity() {
    private lateinit var controller: NveSurfaceController

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        val density = resources.displayMetrics.density
        val main = Handler(Looper.getMainLooper())
        controller = NveSurfaceController(
            NativeRuntimeHost(1, 360f, 800f, density, Executor { main.post(it) }),
        )
        controller.start(NveSource.App(applicationInfo.nativeLibraryDir + "/libnve_app.so"))
        setContent { NveSurface(controller, Modifier.fillMaxSize()) }
    }

    override fun onDestroy() {
        controller.close()
        super.onDestroy()
    }
}
```

# Windows 11 & `react-native-windows` (`hosts/windows-shell`)

`hosts/windows-shell` is a DPI-aware **Win32 + Direct2D / DirectWrite / WIC** desktop shell on the shared C++ host stack (`nve::host_cxx` + `libnve_runtime`). An optional **`react-native-windows` 0.83+ Composition Fabric** component sits on top of it.

## Architecture

1. **Retained model (`NveWinVisualTree`, every OS)**: `RetainedTree` mirrors the runtime's zero-copy scene into owned per-node visuals in O(changed). Geometry-only changes take the cheap `move` path, and resources are re-read only when republished. The model also provides a paint-order walk, hit testing, damage rects, and image-fit and shadow geometry.
2. **Surface controller (`NveWinHost`, every OS)**:
   - app sources: an in-process app, a `cdylib` with state-preserving hot reload, or a paired `nve dev` server;
   - app-state files;
   - presses with matching down/up targets and disabled ancestors;
   - links: `http(s)` / `mailto` only;
   - wheel scrolling with edge chaining, hover, cursors, and text / focus events.
3. **DirectWrite (`NveWinTextMeasurer.hpp`)**: the runtime's text measurer, and the per-node `IDWriteTextLayout`s the painter draws.
4. **Direct2D painter (`NveWinD2DRenderer.cpp`, `NveWinD2DMedia.cpp`)**:
   - shadows, rounded backgrounds and clips, borders, opacity layers;
   - WIC images from `data:` URLs, local files, and inline bytes (UNC and remote hosts are refused);
   - `NVE_DRAW1` canvas lists and text;
   - dirty-rect repaints, with device resources in a per-target `D2DPaintCache`;
   - headless `--screenshot <path.bmp>`.
5. **Native text inputs (`NveWinTextInputs`)**: one Win32 `EDIT` per `TextInput` node. The platform provides IME, clipboard and accessibility. `host::ControlledText` writes rejected or transformed edits back, Enter submits, and focus / blur events are dispatched.
6. **Window manager (`NveWinWindowManager`)**: modal blockers, cancelable close, cascade close, and quit on the last window.

## Build & run (PowerShell)

```bash title="Build, test, and run on Windows 11 (MSVC + Ninja)"
cmake -S hosts/windows-shell -B hosts/windows-shell/build -G Ninja
cmake --build hosts/windows-shell/build
cargo build -p nve-example-kitchen-sink
$env:NVE_TEST_KITCHEN_SINK_DYLIB = (Resolve-Path target\debug\nve_example_kitchen_sink.dll).Path
ctest --test-dir hosts/windows-shell/build --output-on-failure

.\hosts\windows-shell\build\nve_windows_shell.exe --dylib target\debug\nve_example_kitchen_sink.dll
.\hosts\windows-shell\build\nve_windows_shell.exe --pair nve://127.0.0.1:8092 --pair-token dev-secret
```

The model, controller and window-manager suites also build and run on macOS and Linux.

## Embedding in `react-native-windows` Composition Fabric

```bash title="Configure the RNW component (nve_rnw_component)"
cmake -S hosts/windows-shell -B hosts/windows-shell/build-rnw -G Ninja \
  -DNVE_WITH_RNW_FABRIC=ON \
  -DRNW_GENERATED_DIR="C:\path\to\rnw-app\Generated Files"
cmake --build hosts/windows-shell/build-rnw
```

```cpp title="Registering an NVE component in RNW Composition Fabric"
nve::win::NveRnwComponentRegistrationConfig cfg{};
cfg.component_name = L"NveCounterView";
cfg.default_dylib_path = "nve_example_kitchen_sink.dll";
nve::win::register_nve_rnw_component(packageBuilder, std::move(cfg));
```

`nve codegen` `export_rn` also emits a typed `<Name>RnwComponentView.generated.hpp` (registration, typed event callbacks) over the same API.

<Callout kind="warning" title="Windows MSVC notes">
Avoid running two concurrent Ninja MSVC builds that share `/Zi /FS` PDB servers (`mspdbsrv.exe` `C1090`). See [Upstream Notes](/reference/upstream-notes).
</Callout>

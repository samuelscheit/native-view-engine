# Native View Engine (`nve`)

**Native View Engine (`nve`)** is a native-speed, multi-backend UI engine written in Rust and C++20. You author declarative UI once using Rust `rsx!` and fine-grained signals (`nve-dioxus`) — or any custom frontend implementing `NveApp` — and render to **real platform-native views**, **hardware GPU Skia canvases**, and **Web WASM DOM** across 10 host targets from a single zero-copy binary ABI.

There is no embedded JavaScript VM, no JSON bridge serialization, and no per-property FFI chatter. Every frame crosses the Rust-to-host boundary as one contiguous `NVE2` binary delta frame, and `libnve_runtime` publishes the laid-out scene back to native hosts as one zero-copy `NveSceneView` (32-byte `NveNodeRow` rows + 16-byte `NveLayoutRect` rects).

## Architectural Pillars

- **Single Binary IR & Modular C ABI** — Every NVE app module exports a single symbol: `nve_get_interface(uint32_t)`. Hosts resolve only the compact `const` function tables they need (`SURFACE = 1`, `LAYOUT = 2`, `COMPONENT = 3`, `DEV = 4`, `HOST = 5`) in **0.98 ns** with `catch_unwind` panic isolation.
- **10 Native & GPU Host Targets** — macOS AppKit, iOS/iPadOS UIKit + RN components, Windows 11 Win32/Direct2D/DirectWrite + RNW 0.88 components, Linux GTK4/Pango/Cairo, Qt 6 Widgets & GPU Quick Scene Graph, Android JNI/Canvas + Jetpack Compose, SwiftUI, Flutter Impeller (`dart:ffi`), Desktop Skia (Metal/Vulkan/D3D12/`softbuffer`), and Web WASM DOM + Semantic HTML5 SSR.
- **Pluggable Layout Engines** — Zero-cost generic `LayoutEngine` + `TextMeasurer` traits let backends monomorphize pure-Rust **Taffy** or link real C++20 **React Native Yoga** (`nve-layout-yoga`) — or hot-switch between them mid-session via `DynLayoutEngine`.
- **Sub-Second 2-Tier Hot Reload & Live Pairing** — Patch RSX text and styles in `< 50 ms` over binary `NVP1` WebSockets (Tier 1), hot-swap compiled `.dylib`/`.so`/`.dll` logic in `150–400 ms` with state preservation (Tier 2), or stream `NveWireFrame` binary deltas at `~5.18 KB/s` @ 60fps to zero-`cdylib` thin clients over QUIC, WebTransport, and WebSocket.
- **Instant Cold Start & Local-First Sync** — Boot Frame 0 from a schema- and `XXH64`-verified `NVE2` keyframe (`Frame0File` / `frame0.nve2`) + live Taffy layout (`< 2 ms` for 1,000 nodes) alongside crash-atomic `StateFile` (`state.nve`) persistence and a zero-dependency binary CRDT engine (`NveCrdtDelta`).

## Verified Performance Baselines

Measured on Apple Silicon (`arm64`, `Darwin`, 20 cores) from `benchmarks/baseline.json` (`cargo bench -p nve-bench` ; C++ `SceneReader` reads: `nve_host_cxx_bench --json`):

| Pipeline Stage | Median Latency | Throughput / Notes |
| :--- | ---: | :--- |
| `nve_get_interface` lookup / render slice | **0.98 ns / 1.33 ns** | Panic-safe `extern "C"` dispatch |
| `EventRing` decode (256 events) | **5.10 µs** | Direct typed-memory ring, zero JSON |
| `NveValueRef` nested field read | **17.09 ns** | Zero-copy borrow from C++ bump arena |
| `GestureArbitrator` nested scroll | **64.51 ns** | Inline `SurfaceChain` + `FastU32Map` |
| `CommandBuffer` encode / streaming decode (1,000 nodes) | **21.17 µs / 18.05 µs** | ~4.7 GiB/s zero-alloc `CommandRef` |
| Dioxus incremental diff / Tier-1 hot-patch | **931 ns / 1.33 µs** | Real RSX AST hot-patch diff `< 2.5 ms` |
| Web HTML5 SSR (100 / 500 rows) | **12.45 µs / 65.05 µs** | Studio WASM bundle: **285.8 KiB gzipped** |

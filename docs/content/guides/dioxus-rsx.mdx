# Dioxus RSX & Signals (`nve-dioxus`)

`packages/core/dioxus` bridges Dioxus `0.7.10` (`dioxus-core` + `dioxus-signals`) onto `nve-abi` without pulling in `dioxus-html` or any web-specific bloat. A custom `WriteMutations` writer translates VirtualDOM diffs straight into batched `NVE1` `CommandBuffer` frames — measuring **6.83 µs** for initial frame render and **931 ns** for an incremental signal update (`benchmarks/baseline.json`).

## Native Elements & HTML Aliases

`nve-dioxus` exposes a native-first `dioxus_elements` schema supporting both mobile/native element names and familiar HTML aliases:

| Native Tag | HTML Alias(es) | `ComponentKind` | Extra Element Props |
| :--- | :--- | :--- | :--- |
| `view` | `div` | `View` | Standard layout, style, and ARIA props |
| `text` | `span`, `p` | `Text` | Inherits `color` & `font_size` down to inline literal leaves |
| `pressable` | `button` | `Pressable` | Interactive hit-testing + keyboard activation |
| `scrollview` | — | `ScrollView` | Native inertial scrolling + `onscroll` |
| `image` | — | `Image` | `src`, `alt`, `resize_mode` (`cover`, `contain`, `stretch`, `center`) |
| `textinput` | — | `TextInput` | `placeholder`, `value`, `multiline`, `secure_text_entry`, `read_only` |
| `skia_canvas` | `canvas` | `SkiaCanvas` | `draw_list` (`NVE_DRAW1` binary or `nve-draw1;b64,` payload) |

Every element accepts both inline CSS-like `style: "..."` strings and direct typed attributes (`width`, `height`, `min_width`, `max_width`, `flex_direction`, `justify_content`, `align_items`, `flex`, `flex_grow`, `flex_shrink`, `gap`, `padding`, `padding_horizontal`, `padding_vertical`, `margin`, `background_color`, `color`, `border_color`, `border_width`, `border_radius`, `opacity`, `font_size`, `z_index`). Non-ABI inline declarations (`font-weight`, `text-align`, `box-shadow`, `overflow`) are automatically forwarded through `RawPropValue` via `apply_typed_attr_with_raw`.

## Typed Native Events

Event handlers bind strongly typed payloads decoded directly from `EventRing` or zero-copy `NveEventBatchRef`:

- `onpress` / `onclick` → `PressEvent` (`PressEventData { x: f32, y: f32 }`)
- `onlongpress` → `PressEvent` (`PressEventData { x, y }`)
- `onscroll` → `ScrollEvent` (`ScrollEventData { x, y, content_width, content_height }`)
- `oninput` / `onchange` → `TextEvent` (`TextEventData { value: String }`)
- `onsubmit` → `SubmitEvent` (`SubmitEventData { value: String }`)
- `onfocus` / `onblur` → `FocusEvent` (`FocusEventData`)
- `onkeydown` → `KeyEvent` (`KeyEventData { key: String, meta, ctrl, shift, alt }`) — delivered directly via typed `NativeEventKind::KeyDown` (`EventPayload::Key` / `NveDirectEvent`)

<Callout kind="info" title="Automatic Dioxus 0.7 workarounds built in">
`nve-dioxus` handles two upstream `dioxus-core 0.7.10` quirks transparently: it strips the `"on"` prefix from event attributes before invoking `VirtualDom::runtime().handle_event`, and it propagates `text_color` and `font_size` from styled parent `text` wrappers down to unstyled literal leaf nodes. On `wasm32`, a target-gated `FrameTimer` avoids `std::time::Instant::now()` panics.
</Callout>

## Accessibility: ARIA & `tabIndex`

All elements inherit 17 accessibility & testing attributes via `define_a11y_attrs!`, including 12 ARIA and keyboard-focus props forwarded across Web DOM, Apple VoiceOver, Windows UIA, GTK4 AT-SPI, Qt Accessibility, Android TalkBack, and Jetpack Compose semantics:

```rust title="Accessible interactive control in nve-dioxus" highlight="4-11"
rsx! {
    pressable {
        style: "padding: 10px 16px; border-radius: 8px; background-color: #2563eb;",
        test_id: "toggle-sidebar",
        accessibility_label: "Toggle navigation sidebar",
        accessibility_role: "button",
        accessibility_hint: "Expands or collapses the section tree",
        tab_index: "0",
        aria_expanded: if open() { "true" } else { "false" },
        aria_controls: "sidebar-nav",
        disabled: is_locked(),
        onpress: move |_| open.toggle(),
        text { style: "color: #ffffff; font-size: 14px;", "Sidebar" }
    }
}
```

Supported ARIA attributes: `accessibility_label`, `accessibility_role`, `accessibility_hint`, `disabled`, `tab_index`, `aria_checked`, `aria_selected`, `aria_expanded`, `aria_modal`, `aria_live`, `aria_controls`, `aria_labelledby`, `aria_describedby`, `aria_valuenow`, `aria_valuemin`, `aria_valuemax`, plus `test_id`.

## Signals & Binary `SignalArchive` Hydration

`packages/core/dioxus/src/signal_archive/` persists and hydrates Dioxus signals across Tier-2 `cdylib` hot-swaps, process restarts, and crash-atomic `StateFile` (`state.nve`) recovery without JSON or fragile slot indices.

Each signal is keyed by a deterministic 64-bit XXH64 hash of `(component_path, '\0', signal_name)` (`signal_slot_id`), preventing collisions and tolerating added, removed, or re-typed signals across app upgrades:

- **Full archive (`NVE_SIG1`, 28-byte header)** — `magic(8) | version(u32=1) | schema_version(u32) | slot_count(u32) | checksum_xxh64(u64)` followed by sorted `(slot_id: u64, tag: u8, payload)` slots (`Null`, `Bool`, `I64`, `U64`, `F64`, `Str`, `Bytes`, `BinValue`).
- **Incremental signal delta (`NVE_SGD1`, 28-byte header)** — Encodes only dirty `Upsert (1)` / `Remove (2)` signal ops for folding onto a base `SignalArchive` before saving via `StateFile`.

```rust title="Registering persistent signals with SignalRegistry" highlight="5-8,11-15"
use nve_dioxus::signal_archive::{SignalArchive, SignalRegistry};

let mut registry = SignalRegistry::new(1 /* schema_version */);
// Hydrate from previous snapshot / Tier-2 hot-swap bytes
if let Ok(archive) = SignalArchive::decode(&saved_bytes) {
    let report = registry.hydrate_from_archive(&archive);
    println!("Restored {} slots ({} skipped)", report.restored, report.skipped);
}

// Snapshot full state or emit dirty-only delta for SnapshotWal
let full_bytes: Vec<u8> = registry.encode_snapshot();
let dirty_delta: Vec<u8> = registry.take_dirty_delta_bytes();
```

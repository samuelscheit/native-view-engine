# Bi-Directional Codegen (`nve-codegen`)

`crates/nve-codegen` has zero external dependencies beyond `std`, `serde`, and `serde_json`, and powers four code generation pipelines from a single unified IR:

1. **Single-source Core & Scene ABI generation (`cargo nve codegen abi`)** — Emits all 10 checked-in ABI artifacts across C, Swift, Dart, Java, and TypeScript from `specs/nve_core_abi.nve.rs` and `specs/nve_scene_abi.nve.rs`.
2. **Nitro-style 6-target Hybrid FFI (`cargo nve codegen hybrid`)** — Parses declarative Rust `#[nve_hybrid_*]` specs and emits zero-JSON bindings for `rust`, `cpp`, `swift`, `kotlin`, `dart`, and `ts`.
3. **React Native Import (`cargo nve codegen import-rn`)** — Parses RN Fabric `*NativeComponent.{ts,js}` and TurboModule `Native*.{ts,js}` specs (TypeScript or Flow) into zero-JS Rust `nve-dioxus` + C++20 Fabric adapters.
4. **5-Target Component Export (`cargo nve codegen export`)** — Exports one `NveExportSpec` into drop-in wrappers for React Native Fabric, Flutter, SwiftUI, Jetpack Compose, and Web Components.

## Single-Source Core & Scene ABI (`--check` Lock)

Every language binding for `nve_get_interface(1..=5)` and the 64-byte `NveRenderNode` / `NveSceneView` slab is generated from one declarative Rust spec and locked by deterministic 64-bit FNV-1a schema hashes (`NVE_CORE_ABI_SCHEMA_HASH = 0x54A4A32B6F258107`, `NVE_SCENE_SCHEMA_HASH = 0x00F2CF037DB50CC8`).

Generated artifacts follow the `.generated.<ext>` convention (and Java `dev.nve.android.generated` package):

| Layer | Target Language | Generated Artifact |
| :--- | :--- | :--- |
| **Core ABI** | C / C++20 (Fabric Bridge) | `cxx/nve-fabric-bridge/include/nve_abi.generated.h` |
| **Core ABI** | C / Swift (`CNveAbi`) | `hosts/swiftui-kit/Sources/CNveAbi/include/nve_abi.generated.h` |
| **Core ABI** | Dart (`dart:ffi`) | `hosts/flutter-plugin/lib/src/nve_core_abi.generated.dart` |
| **Core ABI** | Java (Android JNI) | `dev.nve.android.generated.NveCoreAbi` |
| **Core ABI** | TypeScript (Web WASM) | `hosts/web-shell/nve_core_abi.generated.ts` |
| **Scene ABI** | C / C++20 (Fabric Bridge) | `cxx/nve-fabric-bridge/include/nve_scene_abi.generated.h` |
| **Scene ABI** | C / Swift (`CNveAbi`) | `hosts/swiftui-kit/Sources/CNveAbi/include/nve_scene_abi.generated.h` |
| **Scene ABI** | Dart (`dart:ffi`) | `hosts/flutter-plugin/lib/src/nve_scene_abi.generated.dart` |
| **Scene ABI** | Java (Android JNI) | `dev.nve.android.generated.NveSceneBuffer` |
| **Scene ABI** | TypeScript (Web WASM) | `hosts/web-shell/nve_scene_view.generated.ts` |

```bash title="Regenerate or verify zero ABI drift in CI"
# Regenerate all 10 Core + Scene ABI artifacts
cargo nve codegen abi

# Fail non-zero if any generated file drifted (normalizes CRLF/LF on Windows)
cargo nve codegen abi --check
```

## Importing React Native Specs (`import-rn`)

Consume existing third-party React Native Fabric components (`*NativeComponent.{ts,js}`) or TurboModules (`Native*.{ts,js}`) from Rust with **zero Hermes**:

```bash title="Generate zero-JS Rust + C++20 adapters from an RN Fabric spec"
cargo nve codegen import-rn path/to/MapViewNativeComponent.ts --out generated/import-rn
```

The parser handles both TypeScript and Flow syntax, resolves re-export wrapper files automatically, and emits:

- A typed Rust `nve-dioxus` component writing `nve_abi::RawPropValue` directly into `CommandBuffer`s.
- A thin C++20 Fabric prop/event adapter compatible with `cxx/nve-fabric-bridge`.

## 5-Target Export (`export`)

Take a single `NveExportSpec` JSON file and emit ready-to-drop wrappers for all five host ecosystems:

| Target (`--target`) | Emitted Artifacts | Host Runtime Integration |
| :--- | :--- | :--- |
| `rn` | `<Name>NativeComponent.ts`, `<Name>NveBridge.{hpp,cpp}`, `<Name>ComponentView.mm`, `<Name>ViewManager.kt` | `RCTNveComponentView` (iOS/macOS) & `NveNativeBridge` (Android) |
| `flutter` | Typed Dart `StatefulWidget` + `dart:ffi` wrapper (`NveDirectEncodable`) | `package:nve_flutter/nve_flutter.dart` (`NveCanvasView` / `NveTextureHostWidget`) |
| `swiftui` | Typed SwiftUI `View` + `NveDirectEncodable` props struct | `NveSwiftUI.NveSurfaceRepresentable` |
| `compose` | Typed Kotlin `@Composable` wrapper | `dev.nve.compose.NveSurface` |
| `web` | Typed Custom Element `<nve-...>` `.js` + `.d.ts` | `wasm-bindgen` `nve-web-shell` |

```bash title="Export a single NveExportSpec to all 5 targets or a subset"
cargo nve codegen export specs/counter_card.json --target all --out generated/export
cargo nve codegen export specs/counter_card.json --target swiftui,compose --out generated/export
```

## Nitro-Style Hybrid FFI (`hybrid`)

Author custom native modules once in a declarative Rust spec (`.nve.rs`) with `#[nve_hybrid_module]` / `#[nve_hybrid_view]` annotations and generate type-safe zero-JSON bindings across 6 languages (`rust`, `cpp`, `swift`, `kotlin`, `dart`, `ts`):

```bash title="Generate 6-language zero-JSON hybrid FFI bindings"
cargo nve codegen hybrid specs/my_audio_module.nve.rs --target all --out generated/hybrid
```

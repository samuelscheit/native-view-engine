# Live Device Pairing (`NveWireFrame` v2)

Live Pairing lets a single workstation run your Rust `NveApp` once and stream real-time UI updates simultaneously to **zero-`cdylib` thin clients** across Skia Desktop, macOS AppKit, Windows Direct2D/RNW, iOS, Android, SwiftUI, Flutter, Qt 6, GTK4, and Web browsers — while ingesting remote touches, scrolls, and keyboard shortcuts back in real time.

## Unified QUIC / WebTransport Architecture (`packages/core/wire-core` + `packages/core/wire`)

### 1. Sans-I/O Wire Framing (`NveWireFrame`, `packages/core/wire-core`)

Every packet on the wire uses a fixed 16-byte little-endian, 8-byte aligned **`NveWireFrame`** v2 header (`magic = "NW"`, `version = 2`, `channel`, `kind`, `flags`, `sequence: u32`, `payload_len: u32`) with a strict pre-allocation `max_frame_bytes` guard and an optional 8-byte canonical **`XXH64`** trailer (`nve_engine::xxh64`):

- **`SceneKeyframe`** — Ships a zero-copy `NveSceneArchive` (`RelocBuf`) keyframe already `XXH64`-verified in its 64-byte header.
- **`CommandDelta`** — Ships direct incremental `CommandBuffer` batches with zero reverse-parsing.
- **`NodePatchDelta`** — Ships compact 24-byte `NveNodePatch` slices (also used by `NveTimelineArchive` for sub-512B widget/Live Activity updates).
- **`SlotChunk`** — Streams out-of-order async / GenUI slot chunks on `NveWireChannel::AsyncSlot`.
- **`EventBatch` / `CrdtDelta` / `Presence` / `HotPatch`** — Multiplexes native binary `EventRing` batches, `NveCrdtDelta` (`XXH64`-verified) state updates, unreliable RFC 9221 presence datagrams, and Tier-1 hot patches over one connection.

### 2. Dual-ALPN QUIC + WebTransport + Happy-Eyeballs `wss://` (`packages/core/wire`)

`NveWireServer` listens on a single UDP socket for both **`h3` (HTTP/3 WebTransport)** and **`nve-wire-2` (raw QUIC)** using a 13-day ECDSA P-256 self-signed dev certificate (with SHA-256 DER hash pinning for browser `WebTransport` `serverCertificateHashes`), plus a single TCP socket serving **`wss://`** (and loopback-only `ws://` for local dev). `NveWireClient` authenticates with constant-time Bearer token verification (`subtle`) and automatically races `wss://` if UDP/QUIC is blocked (Happy Eyeballs, 250ms head start).

| `NveWireKind` | Channel | Direction | Purpose |
| :--- | :--- | :--- | :--- |
| `Hello` / `HelloAck` / `Reject` | `Control (0)` | Bidirectional | Constant-time Bearer token auth + `schema_version` + `session_id` negotiation |
| `SceneKeyframe` / `CommandDelta` / `NodePatchDelta` | `UiScene (1)` | Host → Client | Zero-copy `NveSceneArchive`, incremental `CommandBuffer`, or 24-byte `NveNodePatch` updates |
| `SlotChunk` | `AsyncSlot (2)` | Host → Client | Out-of-order async / GenUI slot streaming |
| `EventBatch` | `InputEvents (3)` | Client → Host | Raw binary `EventRing` batch |
| `CrdtDelta` | `StateSync (4)` | Bidirectional | `NveCrdtDelta` (`XXH64`) state synchronization |
| `Presence` | `Presence (5)` | Bidirectional | Unreliable RFC 9221 QUIC/WebTransport datagrams |
| `HotPatch` / `Ping` / `Pong` / `KeyframeRequest` / `Bye` | `Control (0)` | Bidirectional | Tier-1 hot patches, keepalives, keyframe resync, and clean teardown |

## Running a Paired Session

Start `cargo nve pair` standalone (or pass `--pair` to `cargo nve dev`), then connect thin clients over QUIC, WebTransport, or `wss://`:

```bash title="Host workstation: start unified QUIC/WebTransport + wss:// pairing server"
cargo nve pair \
  --package nve-studio-workspace \
  --host 0.0.0.0 \
  --quic-port 8091 \
  --ws-port 8092 \
  --token dev-secret \
  --width 1280 --height 800 --fps 60
```

:::tabs
::tab{label="Skia Desktop"}
```bash title="Zero-cdylib Skia thin client over QUIC (or Auto Happy-Eyeballs)"
cargo run -p nve-skia-shell -- \
  --pair-connect 127.0.0.1:8091 \
  --pair-transport quic \
  --pair-token dev-secret
```
::tab{label="Web Browser"}
```text title="Open in any desktop or mobile browser (WebTransport h3 or wss:// fallback)"
http://127.0.0.1:8080/?pair=https://127.0.0.1:8091/nve-wire&ws=wss://127.0.0.1:8092/nve-wire&token=dev-secret&cert_hash=<base64-sha256>
```
::tab{label="macOS / Windows / Qt / GTK"}
```bash title="C++20 nve::PairClient thin clients (POSIX + WinSock2)"
# macOS AppKit
./hosts/macos-shell/build/nve_macos_shell \
  --pair-connect 127.0.0.1:8092 --pair-transport ws --pair-token dev-secret

# Windows 11 Direct2D (WinSock2)
.\hosts\windows-shell\build\nve_windows_shell.exe \
  --pair-connect 127.0.0.1:8092 --pair-transport ws --pair-token dev-secret

# Qt 6 / GTK4
./hosts/qt-shell/build/nve_qt_shell --pair-connect 127.0.0.1:8092 --pair-transport ws --pair-token dev-secret
./hosts/gtk-shell/build/nve_gtk_shell --pair-connect 127.0.0.1:8092 --pair-transport ws --pair-token dev-secret
```
:::

When `cargo nve pair` binds its sockets, it prints `NVE_PAIR_READY` along with the QUIC/WebTransport and `wss://` endpoints, certificate SHA-256 hash, and pairing token for automated CI and E2E harnesses.

# Architecture & Design Decisions

## 1. Core Thesis

`native-view-engine` separates **UI authoring**, **state mutation**, and **platform rendering** along one narrow, data-oriented boundary:

- **In-process (Tier 1 default)**: frontends write directly into a single-owner word-table [`NodeStore`](../packages/core/store) via `Transaction::commit_into` -> reusable `ChangeSet`, and backends (`WebBackend`, `SkiaBackend`, `HeadlessBackend`, static-LTO native hosts) implement `StoreBackend` reading `(&NodeStore, &ChangeSet)` directly with zero intermediate encode/decode, zero per-node heap fields [INV:no-noderow-heap-fields], zero vtable dispatch, and zero mirror trees.
- **Cross-boundary (Tier 2 — dev `dlopen` hot-reload, C ABI hosts, `nve-wire`, Frame-0 replay)**: the same `ChangeSet` encodes as table-major `NVE2` binary wire frames (`nve_store::wire` -> `StoreWireReplica`) alongside flat C ABI `NveSceneView` + `EventRing` (`nve-abi` / `nve/generated/nve_abi.generated.h`).

This eliminates React Native's JS reconciler, JSI per-prop crossings, `RawProps` string parsing, and `folly::dynamic` serialization while preserving **real platform-native views** (iOS `UIView`, Android `View`) and **native RN Fabric ecosystem compatibility** — and lets one identical `NodeStore` / `NVE2` pipeline drive **Skia** (macOS, Windows, Linux, iOS, Android), **Web DOM/WASM**, and **Headless** test hosts.

## 3. Architectural Decision Records (ADRs)

### ADR-001: Word-Table `NodeStore` In-Process + Table-Major `NVE2` Cross-Boundary
- **Decision:** Every mutation producer writes coalesced typed fields directly into a single-owner word-table `NodeStore` (`Transaction::commit_into` -> reusable `ChangeSet`), and every in-process backend implements `StoreBackend` reading `(&NodeStore, &ChangeSet)` directly with zero intermediate encode/decode, zero per-node heap allocations, zero vtable indirection, and zero mirror trees. When updates must cross a `dlopen` / C ABI / network / Frame-0 replay boundary, `nve_store::wire` encodes the same `ChangeSet` into table-major `NVE2` frames and applies them into a `StoreWireReplica` whose `(&NodeStore, &ChangeSet)` drives the exact same `StoreBackend` path.
- **Why:** Eliminates in-process serialization/deserialization overhead, double-flush hydration mismatches, and component-kind enum coupling across Web WASM, Skia, Headless, and static-LTO native hosts, while keeping cross-boundary FFI/JNI/network transport compact, schema-hashed (`xxh64`), and deterministically replayable through a single decoder.

### ADR-002: Framework-Agnostic Engine With Dioxus First
- **Decision:** `nve-store` and `nve-engine` have zero dependency on `dioxus-core` [INV:core-zero-dioxus]. `nve-dioxus` plugs into `nve-store` by translating `WriteMutations` directly into a `NodeStore` `Transaction` (with optional `NVE2` wire emission for cross-boundary frames).
- **Why:** We get production-grade `rsx!`, signals, and template hot reload on day 1, while keeping the core compile graph tiny (<300ms) and leaving the door open for a custom zero-VDOM reactive frontend or non-Rust frontends later.

### ADR-003: Model A (Sized Surface Island) Across RN Fabric, SwiftUI, Flutter & Compose
- **Decision:** Retire deep `facebook::react::ShadowNode` tree injection (`commit_rn_shadow_tree` no-op stub) and standardize every host framework embedding (RN Fabric `RCTViewComponentView` / Android `ViewGroup` / RNW Composition `ComponentView`, SwiftUI, Flutter, Jetpack Compose) on **Model A (Sized Surface Island)**:
  - Outer layout coordination uses `NVE_IFACE_LAYOUT = 2` (`measure_surface(constraints) -> NveIntrinsicSize` with `first_baseline`/`last_baseline`, `DRY_RUN`/`IDEAL` flags, and `on_intrinsic_size_invalidated` host callback) so NVE participates cleanly in the host's native layout tree and 120Hz VSync cycle.
  - Inner layout & commits are owned by NVE (`NveSceneView`), with foreign host child views mounted inside `<NativeView>` slot holes using back-canvas → host-child (native clip + gesture arbitration via `hit_test`) → front-overlay-canvas layering.
- **Why:** Eliminates fragile coupling to private RN C++ internals (Folly/glog/boost/per-minor `ShadowNode` ABI drift and RNW C++/WinRT divergence), preserves full NVE feature parity (CSS Grid, `sticky`, `:hover`/transitions, gradients, SVG, BiDi text), and shares one architecture identically across RN, SwiftUI, Flutter, Compose, and standalone native shells.

### ADR-004: Unified 2-Engine Layout via Host-Owned `packages/core/runtime`
- **Decision:** Collapse NVE's 5 layout engines down to **2**:
  1. **Browser CSS** on Web (`packages/backends/web` implements `StoreBackend` and consumes pre-layout `(&NodeStore, &ChangeSet)` word-table diffs directly in-process; `taffy` and `nve-runtime` are never linked on WASM).
  2. **Host-owned Rust `packages/core/runtime` (`libnve_runtime`)** using `Taffy` by default (with optional `Yoga` via `StoreLayoutEngine` for RN Yoga parity) and an LRU-cached OS `TextMeasurer` C callback (`CoreText`, batched Android `StaticLayout`, Pango, `QFontMetrics`, `DirectWrite`), publishing extended `NveSceneView` directly across C ABI to all 10 native hosts.
- **Why:** Keeping `Taffy` in the host runtime (and statically LTO-linking `app_rlib + nve-runtime` into one binary in release `nve build`) keeps Tier-2 hot-swappable app `cdylib`s thin and fast, preserves text-measurement caches and scroll/hover state across `dlopen` swaps, supports zero-dylib paired thin clients (`nve-wire`) and Frame-0 instant boot, deletes ~8,000–11,500 LOC of duplicated C++/Dart layout & decoder code (`flexbox_solver.cpp`, `yoga_layout.cpp`, `shadow_tree.cpp`, `flex_layout.dart`, `command_decoder.dart`), and brings CSS Grid, RTL, `sticky`, `:hover`/transitions, gradients, and SVG uniformly to every native host.

### ADR-005: Standard-HTTP Integer-Keyed CBOR RPC (`nve-rpc` / `nve-server`) With Pluggable Codec & Runtime-Agnostic Core
- **Decision:** Avoid inventing a custom binary RPC framing envelope or lockstep network codec. Standardize fullstack RPC on plain HTTP (`POST /rpc/<Procedure::NAME>`, standard HTTP status codes, Connect-compatible JSON protocol errors, `Nve-Invalidate` cache-tag header) with RFC 8949 integer-keyed CBOR (`minicbor`, `application/cbor`) behind a pluggable `RpcCodec` seam (allowing Protobuf/`prost`/`buffa` to plug in cleanly). Keep `nve-rpc` and `nve-server` strictly sans-I/O (zero `tokio`/`hyper`/`axum`/`serde_json`/`dioxus`/`web-sys`) and isolate HTTP server/client I/O in leaf adapters (`nve-http-hyper`, `nve-http-web`, future `nve-http-wasip2` / `nve-wire`).
- **Why:** Installed mobile binaries require forward/backward schema evolution (integer-keyed CBOR maps + open `Unknown(u32)` enums skip unknown fields/variants without breaking older clients) while keeping the wire footprint compact (~52% of JSON on `IssueSummary` benchmarks, 3.5–4.4× faster encode and 1.2–1.4× faster validated decode) and avoiding heavy framework-coupled client crates. Standard HTTP semantics preserve CDN/proxy/DevTools observability and progressive 0-JS HTML `<form>` (`303`/`204`/`422`) compatibility on the same `Procedure` contracts.

### ADR-006: Flat SoA Query Cache (`nve-query`) + Dense Recycled Slot Signals (`nve-query-dioxus`)
- **Decision:** Keep the query/mutation engine (`packages/framework/query`) strictly sans-I/O and UI-agnostic using cache-line-aligned 64-byte `QueryMeta` slots, a flat `TagEdge` inverted index for O(k) tag invalidation, an O(1) `wildcard_epoch` counter, and optimistic patch layers folded strictly outside the cache lock. Bridge it to Dioxus 0.7 (`packages/framework/query-dioxus`) via a single transport-erased `ErasedQueryClient`, one dense recycled `Signal<u32>` per active slot, provider-scoped fetch/action tasks, and non-polling `DioxusSurface::poll_work` host wakeups (`WebAsyncWakeGuard` microtask on Web, `METHOD_WINDOW_REQUEST_FRAME` on Skia plus `#[cfg(test)]`-only `DioxusDesktopApp` inside binary-only `hosts/skia-shell` until Track 1B-2 `packages/core/runtime` exposes it as a shared library crate).
- **Why:** Separates cache correctness, deduplication, and SSR `NVEQ` v2 dehydration/hydration from UI/runtime lifecycles, guarantees zero-allocation cache reads (`~14.6 ns`) and tag invalidations (`~16.6 ns`), prevents child component unmounts from stranding shared fetches or leaking optimistic layers, and runs one identical UI crate (`examples/fullstack-issues/client`) across Web WASM, 0-JS HTML `<form>`, and Native Skia.

### ADR-007: Out-of-Order DSD Streaming SSR + Mid-Stream Async WASM Hydration (`nve-ssr` / `nve-backend-web`)
- **Decision:** Run `!Send` Dioxus SSR surfaces on a dedicated `LocalSet` worker pool (`SsrLocalPool`), returning buffered Light-DOM `HttpBody::Full` when zero `<QuerySuspense>` boundaries suspend and `HttpBody::Stream` (`ChannelBody`) over an ephemeral `<div data-nve-dsd-host>` Declarative Shadow DOM host when boundaries suspend. Emit `NVEQ` v2 `seq=0` (critical settled queries + `StreamPending` markers) + `<template data-nve-q-ack="0">` strictly before `<script type="module" async src="...">`, emit per-slot `NVEQ` v2 deltas (bound via `data-nve-slot-for="{id}"`) strictly before each `<div slot>` chunk and its trailing `<template data-nve-slot-ack="{id}">` — the slot-ack is the single atomic completion marker for both data and markup: the promotion adopts only acked chunks (never a closed-but-unacked or truncated `<div>`) and clients ingest a slot-bound payload only once its ack is parsed or its slot was adopted, so no TCP split can hydrate data against a still-visible fallback (or vice versa); a slot's chunk `<style data-nve-ssr-chunk>` (always emitted strictly before its `<div slot>`) is hoisted and hash-seeded only once a next sibling proves it whole (never on `readyState`), and a truncated one is dropped unseeded so the client re-inserts its rules; `<QuerySuspense>` IDs come from one allocator shared by server and client (auto `_sN`, explicit IDs never start with `_`, so the namespaces are disjoint); keep `PRE_HYDRATION_REPLAY_SCRIPT_TAG` after `<div id="app">` and hold each streaming render's worker slot (`OwnedSemaphorePermit`) until the body ends; promote DSD atomically into Light DOM on WASM boot with top-down structural hydration (`mismatches = 0`), stream late deltas into `QueryClient` via a `MutationObserver` on hidden `[data-nve-dsd-host]`, and fail-close incomplete streams via `QueryClient::finish_ssr_stream()` on `<template data-nve-stream-end>` / `DOMContentLoaded`. Enforce strict zero-inline-JS CSP (`script-src 'self' 'wasm-unsafe-eval'`) with per-request CSPRNG `style_nonce`.
- **Why:** Delivers instant 0-JS out-of-order streaming paint via browser-native Declarative Shadow DOM while allowing WASM to boot and become interactive mid-stream behind slow boundaries with zero duplicate RPCs, zero inline JS, zero hydration mismatches, and immediate server-side `VirtualDom`/RPC cancellation when clients disconnect.

### ADR-008: One Scene ABI, No C++ Bridge (`NveSceneView` + `SceneReader`)
- **Decision:** Every host reads exactly one scene ABI [INV:single-scene-abi]: `NveSceneView`, borrowed between `scene_acquire` / `scene_release` from `libnve_runtime`, which publishes `NodeStore`'s own slabs (32-byte `NveNodeRow`s, 16-byte `NveLayoutRect`s, text / children slabs, `dirty` / `moved` / `removed` sets, `NveTableView`s, scroll offsets, dirty resources) validated against `NVE_RUNTIME_SCHEMA_HASH`. Each host language has one static reader named `SceneReader` (`packages/core/host-{cxx,swift,java,dart,ts}`). The former 64-byte per-node scene records (and their table / metadata / schema-hash companions), the web-shell scene mirror, and the C++ Fabric bridge (its C++ shadow tree, Yoga / flexbox solver, mock JSI, host C API, and RN component wrapper) are deleted and banned. React Native embeds NVE only as a Model A island over the runtime host (ADR-003); generic native-view codecs live in `packages/modules/native-views`.
- **Why:** A second per-node record meant a second publisher, a second schema hash, and a materialization pass per frame on every host; the C++ bridge duplicated layout, decoding, and event plumbing that `libnve_runtime` owns. One view read straight from the store's slabs keeps every host O(changed) with zero per-node copies, and one reader name per language keeps host code and docs uniform.

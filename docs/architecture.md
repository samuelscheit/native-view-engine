# Architecture & Design Decisions

## 1. Core Thesis

`native-view-engine` separates **UI authoring**, **mutation handoff**, and **platform rendering** along one narrow, zero-overhead boundary:

- **In-process (Tier 1 default)**: monomorphized direct typed `RenderSink` calls (`DioxusSurface::flush_into<S: RenderSink>`) with zero intermediate encode/decode, zero vtable dispatch, and zero out-of-band side-channels (`WebBackend`, `SkiaBackend`, `HeadlessBackend`, and static-LTO native hosts).
- **Cross-boundary (Tier 2 — dev `dlopen` hot-reload, C ABI hosts, `nve-wire`, Frame-0 replay)**: one shared `BatchSink` (`impl RenderSink`) serializing the same typed mutations into one flat binary `CommandBuffer` (`nve-abi` / `include/nve_abi.generated.h`) plus `EventRing`.

This eliminates React Native's JS reconciler, JSI per-prop crossings, `RawProps` string parsing, and `folly::dynamic` serialization while preserving **real platform-native views** (iOS `UIView`, Android `View`) and **native RN Fabric ecosystem compatibility** — and lets the exact same typed `RenderSink` / binary IR drive **Skia** (macOS, Windows, Linux, iOS, Android), **Web DOM/WASM**, and **Headless** test hosts.

## 3. Architectural Decision Records (ADRs)

### ADR-001: Direct Typed `RenderSink` In-Process + Single `BatchSink` Cross-Boundary
- **Decision:** Every mutation producer streams coalesced typed mutations into a monomorphized `RenderSink` (`flush_into<S: RenderSink>`) with zero intermediate encode/decode, zero vtable indirection, and zero out-of-band `sync_*_from` side-channels. When bytes must cross a `dlopen` / C ABI / network / Frame-0 replay boundary, one shared `BatchSink` (`impl RenderSink`) serializes both core ops and extended props (`nve.ext.*` typed binary payloads) into a single contiguous `CommandBuffer` (`u32` header + TLV opcodes), which every Rust backend decodes through the shared `replay_command_buffer_into` into its own `RenderSink` impl.
- **Why:** Eliminates in-process serialization/deserialization overhead and double-flush hydration mismatches on Web WASM, Skia, Headless, and static-LTO native hosts, while keeping cross-boundary FFI/JNI/network transport flat, batched, losslessly typed, and deterministically replayable through a single decoder.

### ADR-002: Framework-Agnostic Engine With Dioxus First
- **Decision:** `nve-engine` has zero dependency on `dioxus-core`. `nve-dioxus` plugs into `nve-engine` by coalescing `WriteMutations` and flushing directly into any `S: RenderSink` (or lazily into `BatchSink` for cross-boundary frames).
- **Why:** We get production-grade `rsx!`, signals, and template hot reload on day 1, while keeping the core compile graph tiny (<300ms) and leaving the door open for a custom zero-VDOM reactive frontend or non-Rust frontends later.

### ADR-003: Model A (Sized Surface Island) Across RN Fabric, SwiftUI, Flutter & Compose
- **Decision:** Retire deep `facebook::react::ShadowNode` tree injection (`commit_rn_shadow_tree` no-op stub) and standardize every host framework embedding (RN Fabric `RCTViewComponentView` / Android `ViewGroup` / RNW Composition `ComponentView`, SwiftUI, Flutter, Jetpack Compose) on **Model A (Sized Surface Island)**:
  - Outer layout coordination uses `NVE_IFACE_LAYOUT = 2` (`measure_surface(constraints) -> NveIntrinsicSize` with `first_baseline`/`last_baseline`, `DRY_RUN`/`IDEAL` flags, and `on_intrinsic_size_invalidated` host callback) so NVE participates cleanly in the host's native layout tree and 120Hz VSync cycle.
  - Inner layout & commits are owned by NVE (`NveSceneView`), with foreign host child views mounted inside `<NativeView>` slot holes using back-canvas → host-child (native clip + gesture arbitration via `hit_test`) → front-overlay-canvas layering.
- **Why:** Eliminates fragile coupling to private RN C++ internals (Folly/glog/boost/per-minor `ShadowNode` ABI drift and RNW C++/WinRT divergence), preserves full NVE feature parity (CSS Grid, `sticky`, `:hover`/transitions, gradients, SVG, BiDi text), and shares one architecture identically across RN, SwiftUI, Flutter, Compose, and standalone native shells.

### ADR-004: Unified 2-Engine Layout via Host-Owned `packages/core/runtime`
- **Decision:** Collapse NVE's 5 layout engines down to **2**:
  1. **Browser CSS** on Web (`packages/backends/web` consumes pre-layout typed `RenderSink` mutations directly in-process; `taffy` and `nve-runtime` are never linked on WASM).
  2. **Host-owned Rust `packages/core/runtime` (`libnve_runtime`)** using `Taffy` by default (with optional `Yoga` via `LayoutEngine` trait for RN Yoga parity) and an LRU-cached OS `TextMeasurer` C callback (`CoreText`, batched Android `StaticLayout`, Pango, `QFontMetrics`, `DirectWrite`), publishing extended `NveSceneView` directly across C ABI to all 10 native hosts.
- **Why:** Keeping `Taffy` in the host runtime (and statically LTO-linking `app_rlib + nve-runtime` into one binary in release `nve build`) keeps Tier-2 hot-swappable app `cdylib`s thin and fast, preserves text-measurement caches and scroll/hover state across `dlopen` swaps, supports zero-dylib paired thin clients (`nve-wire`) and Frame-0 instant boot, deletes ~8,000–11,500 LOC of duplicated C++/Dart layout & decoder code (`flexbox_solver.cpp`, `yoga_layout.cpp`, `shadow_tree.cpp`, `flex_layout.dart`, `command_decoder.dart`), and brings CSS Grid, RTL, `sticky`, `:hover`/transitions, gradients, and SVG uniformly to every native host.

### ADR-005: Standard-HTTP Integer-Keyed CBOR RPC (`nve-rpc` / `nve-server`) With Pluggable Codec & Runtime-Agnostic Core
- **Decision:** Avoid inventing a custom binary RPC framing envelope or lockstep network codec. Standardize fullstack RPC on plain HTTP (`POST /rpc/<Procedure::NAME>`, standard HTTP status codes, Connect-compatible JSON protocol errors, `Nve-Invalidate` cache-tag header) with RFC 8949 integer-keyed CBOR (`minicbor`, `application/cbor`) behind a pluggable `RpcCodec` seam (allowing Protobuf/`prost`/`buffa` to plug in cleanly). Keep `nve-rpc` and `nve-server` strictly sans-I/O (zero `tokio`/`hyper`/`axum`/`serde_json`/`dioxus`/`web-sys`) and isolate HTTP server/client I/O in leaf adapters (`nve-http-hyper`, future `nve-http-wasip2` / browser `fetch` / `nve-wire`).
- **Why:** Installed mobile binaries require forward/backward schema evolution (integer-keyed CBOR maps + open `Unknown(u32)` enums skip unknown fields/variants without breaking older clients) while keeping the wire footprint compact (~52% of JSON on `IssueSummary` benchmarks, 3.5–4.4× faster encode and 1.2–1.4× faster validated decode) and avoiding heavy framework-coupled client crates. Standard HTTP semantics preserve CDN/proxy/DevTools observability and progressive 0-JS HTML `<form>` (`303`/`204`/`422`) compatibility on the same `Procedure` contracts.

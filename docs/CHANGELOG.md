## Track 1B-2 — Host-Owned Layout & Runtime

- **Landing hardening (runtime ABI v2)**: `NVE_RUNTIME_ABI_VERSION = 2` for the 24-slot vtable. **P0**: `SurfaceState` no longer caches the replica `ResourceStore` address (inline in `SurfaceRuntime`, dangling after a move); `PublishedResources::{None, Replica, App(*const ResourceStore)}` resolves the replica at read time and pins only boxed app stores (guarded by `resource_payload_survives_moving_the_runtime_after_publish`, which reuses the freed heap block). Dense tables publish null owners and at most `capacity()` rows (`commit.rs` + `NodeStore::table_storage`, guarded by `dense_tables_publish_null_owners_and_rows_within_node_capacity`). Host text measurer clamps weights to `100..=900` and skips non-finite / non-positive font sizes without a host call. `RuntimeSceneReader::open` rejects non-ascending / duplicate `scroll_offsets` (`SceneError::UnsortedScrollOffsets`). `NveBufferSlice` / `NveEventBatch::from_slice` and `CAbiAppAdapter::set_props` pass NULL for empty slices; opaque replica resources share one `Arc`; scroll publication reads each offset once (`ScrollOffsets::visual_shift_with`).
- **Slice 2B-0 — Embedding-host runtime hooks**: `NveRuntimeApi` grows to 24 slots described once by `RUNTIME_API_SLOTS` (drives Rust offset locks, `NVE_RUNTIME_SCHEMA_HASH`, and the generated C vtable + `nve_runtime_api_slots_complete`): `set_text_measurer`, `set_props`, `drain_emitted_events`, `snapshot_state` / `restore_state`, `apply_hot_patch`, and scene-guarded `resource_payload` (canonical bytes cached in `ResourceStore::encoded`; replica stores keep codec-less module kinds as opaque exact bytes instead of failing the frame). `NveRuntimeSceneView` publishes `NveScrollOffset` visual shifts (112 bytes on 64-bit). `nve-runtime` builds a `cdylib`, `NveRuntime.cmake` expands list arguments, and host-cxx `RuntimeSession` wraps every hook (C++20 `test_runtime_hooks` + shared `nve2_writer.hpp`). `nve-docs-site` embeds docs via `CARGO_MANIFEST_DIR`-relative `include_str!` so rustc-wrapper caches stay valid across worktrees.

## Docs, Web Foundations & Wave 14 (Zero-Copy, DRY & Production Docs)

- **Merge `main` (Slice 1c Round-1/Round-2 hardening) into the NodeStore integration line** — every `main` fix is ported onto the NodeStore word-table pipeline instead of reviving `LayoutProps`/`StyleProps`/`RawStyleProps`/`CommandBuffer`:
  - **Inline style grammar (`nve-components`)**: new `css_values.rs` (zero-alloc, ASCII case-insensitive keywords, strict `rgb()`/`rgba()` + 3/4/6/8-digit hex, `px` bounded by `MAX_STYLE_SCALAR`) and `css_shorthand.rs` (all-or-nothing 1–4 value `padding`/`margin`, `border` with CSS omitted-value rules, `flex` with `flex: <n>` = `<n> 1 0%`, `none`/`auto`/`initial`, unitless basis only `0`). `css_decl.rs` seals every value at ingress (non-negative sizes/gaps/flex factors/border widths/radii, positive `font-size`, scalars within `1e7`), replacing headless `validate.rs`. `flex-basis` lives in `Layout::flex_basis` (no raw-style or `LayoutExt` lane). Shorthand ranks (`shorthand < axis < longhand`) keep standalone precedence order-independent.
  - **`currentColor` borders**: `css.rs` resolves a symbolic border color after the whole declaration list against `effective_text_color` (nearest explicit `Typography` color); the Dioxus writer tracks `current_color_borders` (inline beats standalone) and re-resolves them at the end of every transaction, so own-color, ancestor-color, and reparent changes converge (O(k·depth), writes only on change).
  - **Streaming SSR**: `StreamSlotState::{Unmounted, Pending, Resolved}` replaces `is_stream_slot_resolved`; slot placement rejects any `<form>`/`<select>` ancestor and a table foster-parent trap as the nearest non-`<QuerySuspense>` ancestor (`AncestorTag::is_suspense_wrapper` from `StreamBoundary::suspense`). `0%` is never written as unitless `0`. HEAD's session-based `seed_ssr_hashes` stays (main's `SsrHashSeeder` closures dropped); `seed_all_ssr_styles` seeds only complete chunk styles. E2E selectors use `data-testid`.
  - **Tests**: main's old-API tests were ported to NodeStore (`css_tests.rs`, dioxus style precedence/`currentColor`/alloc guards, web flex-basis/escaping/streaming placement, `ssr_hardening_tests`, query-dioxus registry/retry tests).
- **Track 1B-1e complete — static host runtimes, lossless hybrid props, and permanent codegen gates**
  - **All 6 hybrid targets on static runtimes**: generated Rust uses `nve_abi::hybrid`; C++20, Swift, Kotlin/JNI, Dart, and TypeScript use `packages/core/host-{cxx,swift,java,dart,ts}` (Swift splits into `NveHost` plus the C-ABI `NveHostAbi` target with `NveValueTree`). Emitters keep only spec-specific code; static ABI data renders from Askama 0.16 `templates/`.
  - **Lossless `NveValue` direct props**: `HybridType::Value` props keep their true `NveValue` tags on every target (C++ / Swift `NveValueTree`, Dart `writeDynamicValue`, Kotlin / TS inline `writeTo`, Rust `decode_value_ref`), never a scratch `BinWriter` wrapped in `Bytes`; `value_direct_props_keep_true_tags_on_all_6_targets` guards all 6.
  - **`[T; N]` codec parity**: C++20 (`std::array`, passed as `const&`) and Swift (`[T]`, `Array(repeating:count:)` defaults) now encode `FixedArray` as an exact-length `Array` like Rust, Dart, and TypeScript, instead of `Null`. New host primitives `BinReader::begin_array_exact` (C++), `BinReader.beginArray(exactly:)` and `BinWriter.beginArray(count:exactly:)` (Swift) reject any other count (`Truncated` when shorter, `TooLarge` when longer); Swift `[T; N]` props cross as `Bytes` like `Vec`. Validation caps `[T; N]` at 4,096 elements, nested dimensions multiplied (see Pass-3 below). Compiled C++20 (ASan/UBSan) and Swift 6 drivers round-trip `[u32; 4]`, `[PodStruct; 2]`, and `Option<[u8; 3]>` in a non-POD struct and reject wrong lengths; Kotlin still rejects `[T; N]` at codegen.
  - **Pass-2 review fixes (`[T; N]` everywhere, C type names, 53-bit gate)**
    - C++ `Option<[T; N]>` / `Result<Option<[T; N]>, String>` returns decode from `NveHybridOwnedBytes` (only `NveHybridOpt*` options read `is_some`).
    - POD `[T; N]` (nested too) crosses the C ABI element by element: C declares `T name[N][M]`, C++ `to_abi` / `from_abi` loop with per-element enum casts and struct conversions (no `memcpy`), and Swift bridges C tuples through `withUnsafe(Mutable)Bytes(of:)` with `toAbi() throws` rejecting wrong counts (`BinError.requireCount`). Structs sort after the structs they hold through options, `Vec`s, and arrays.
    - `[T; N]` length is capped at 65,536; Swift `decodeBin` opens the map before building defaults.
    - Validation rejects enum / struct names whose C type `NveHybrid<Name>` spells another one (`Status`, `<Module>VTable`, `Raw<Struct>`, `Opt<T>`); the Rust edge fixture's `Status` is now `Pulse`, and that spec compiles as C++20 and Swift.
    - A live Rust provider backs the compiled C++20 (ASan/UBSan) and Swift (ASan) fixed-array drivers: codec, POD, option / `Result` returns, and `[T; N]` view props.
    - The 53-bit scanners move to `nve-arch-invariants::codegen_53bit`. They strip `//` comments before checking, and also flag `0X{..}`, `0x{hi:08X}{lo:08X}`, `0x{hi:08X}00000000`, and alternate-form `{h:#018X}` / `{h:#x}`.
    - `HybridDefaultValue::scalar_literal` returns a `NonScalarDefault` that the Dart, Rust, and Swift targets match exhaustively. The test `rustc` helper reads each `nve_abi` rlib once and names the directory it searched when no wire-enabled rlib exists; the Swift e2e test uses it too.
  - **Pass-3 review fixes (no reachable panic, element caps, Dart / TS proven, one type-name registry)**
    - The C / C++ emitter has no `unreachable!`: `c_value_type` returns `Option` (scalars, enums, POD structs), `require_c_value_type` / `c_fn_type` return `Result`, and a struct with a field without a C form (an opaque `*const [T; N]`) stays C++-only. Static C functions may point only to `void`, scalars, enums, and structs: validation rejects `*const [T; N]` (C would need `T (*)[N]`), `*const String`, and the like.
    - `[T; N]` holds 1..=4,096 elements with every nested dimension multiplied (`checked_mul`), replacing the 65,536-per-dimension cap: Swift's Clang importer drops C struct array fields over 4,096 elements, and `[[u64; 65536]; 65536]` (32 GiB) used to pass.
    - Dart POD structs carry nested `[[T; M]; N]` as `@ffi.Array.multi([N, M])` `ffi.Array<ffi.Array<T>>` with recursive length-checked `_writeAbi` / `fromAbi`; Dart `decodeBin` builds a missing field's default only after the map is read. A live Dart VM driver against the Rust cdylib, a strict `tsc` + Node driver, and `dart analyze` of the Rust edge spec now prove the fixed-array parity claims. They caught two bugs, now fixed: Dart emitted `X({})` for an event or props class without parameters, and TypeScript decoded a too-long `[T; N]` as `truncated` instead of `tooLarge`.
    - One generated-type-name registry (`validate/generated_names.rs`) checks user names against generated ones and generated ones against each other, in the C-family and Rust namespaces: runtime types, `NveHybrid<Name>`, Rust `NveHybridRaw<Name>`, `NveHybridOpt<T>`, `NveHybrid<P>VTable`, `Hybrid<P>Spec`, `<P>Client`, `<P>HybridClient`, `<P>Hybrid`, `<V>Props`, `<V><Event>Event`, `<V>WasmExports`, `<Stem>HybridFile`, `<Stem>HybridSchema`. `struct Frame` beside `struct RawFrame` is accepted again; options of static C functions get their `NveHybridOpt<T>`.
    - `HybridStructSpec::is_pod` peels nested arrays and threads one borrowed `visited` path (no stack overflow on an unvalidated `struct A { x: [A; 1] }`); `HybridType::fixed_array_dims` is shared by the C, Swift, and Dart emitters and validation.
    - The 53-bit scanners lex Rust: `//` and nested `/* */` comments are removed only outside string, raw-string, and char literals (across lines; comment-free lines allocate nothing), and they also flag `0x10000000{lo:08X}`, `0x{hi:08X}_{lo:08X}`, and `{h:>#018X}`.
    - The fixed-array fixture adds `[u32; 1]` (a scalar in Swift's C import) and `[[FixedPoint; 1]; 2]`, an `Option<[u8; 3]>` argument, `Option<FixedPod>` through `NveHybridOptFixedPod`, `try_tag` `Ok(None)`, and wrong inner-row decodes; the Swift driver also runs with `-O`. Prop defaults are a plain `DefaultLiteral` enum; C++ array loops bind `_nve_i<depth>`. Dart and TS test helpers move to `tests/common/{dart,ts}.rs`.
  - **Pass-4 review fixes (opaque C handles, one layout per C option, block-safe 53-bit scan)**
    - Structs without a C form that static C functions point to are declared as file-scope incomplete typedefs (`typedef struct NveHybridX NveHybridX;`), so the header passes `clang -std=c11` and `clang++ -std=c++20` with `-Werror`; a test compiles both.

  - **Test tooling**: `common::tool_available("kotlinc")` probes `-version`, so `require_tool("kotlinc")` honors `NVE_REQUIRE_KOTLINC` like every other tool.

- **Slice A Pass-5 polish (`nve-backend-headless`)**: the hit-walk scratch moves from a `Mutex` to a `Cell` taken for each query. `HeadlessBackend` is neither `Send` nor `Sync` (raw table views), so the lock bought nothing, and `Cell::take` never allocates. The buffer only grows, so it keeps its high-water capacity, and a debug assert checks that every level truncated its keys. Single-level detection stops at the first sibling on another level. The 64-key stack sort and the scratch sort run out of line, so a deep single-level walk carries no 512 B key buffer per frame. `aspect_ratio_content_size` returns `None` for a transfer that overflows `f32` instead of a 0-wide box, which used to wrap text at 0. Guards: > 64 shuffled mixed-`z` siblings with ties plus a nested > 64 container that misses (scratch reallocated mid-walk, empty after each query, same target on a second query), a 512-deep chain hit-tested on a 512 KiB thread through a non-recursive stub layout engine, the overflowing-ratio text wrap (fails with the old clamp), and the root round trip with non-default `ROOT` typography and a `display: contents` sibling outside the nested root (fails without either `invalidate_all` reset).
- **Slice A Pass-4 polish (`nve-backend-headless`, `nve-dioxus`)**: headless hit order no longer degrades with `z_index` variety. The Pass-3 level-by-level `TopmostFirst` scan was O(levels·N), so O(N²) for distinct `z_index` siblings, and paid three `paint_z` reads per sibling even with one level. Sibling lists with 0–1 children or a single level (one min/max scan, `Layout` read only for non-zero `z_index`) now walk in reverse DOM order. Mixed levels sort unique `(z, index)` keys with the allocation-free `sort_unstable`: in a stack buffer up to 64 siblings, beyond that in stack-disciplined scratch the backend keeps across queries, locked only on that path. Worst-case hits (target visited last, release, loaded machine, same bench on the Pass-3 tree vs now): distinct `z_index` 64 / 1,000 / 4,000 siblings 73.0 µs / 17.8 ms / 298.7 ms → 3.1 µs / 44.0 µs / 218.0 µs; uniform 3.6 / 49.9 / 212.2 µs → 2.3 / 32.3 / 127.2 µs. Text with `aspect-ratio` wraps at a transferred width even when padding clamps it to 0 (`aspect_ratio_content_size` returns `Option`, separating "no transfer" from a 0-wide content box). `invalidate_all` (also run on a layout-root switch) resets inherited `direction`/typography and `was_contents`, so slots outside a nested root read like a fresh engine's.
